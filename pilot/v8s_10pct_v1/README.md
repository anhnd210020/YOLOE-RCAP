# YOLOE-v8-S 10% pilot preparation

This directory contains the pilot preparation code and selected manifests. Generated datasets, caches, locks, and runs are produced on the preparation host. The main experiment is stage-1 text-prompt segmentation for 30 epochs on one GPU, with full LVIS minival evaluation (4,809 images). Official YOLOE files remain unchanged.

## Requirements and sampling

On the later preparation host, install the small pure-Python dependency `ijson` in the environment that runs `make_subset.py` and `verify_subset.py`. The existing YOLOE Python environment supplies NumPy and Ultralytics for conversion, caches, and training. Do not run the official Objects365 converter: it recreates its labels directory.

Each source is sampled separately at the **official JSON image_id record** level. Distinct GQA/Flickr30k image_id records may reference the same physical JPEG and remain separate. For each source, `K=floor(0.1*N_images)`. The lowest SHA256 keys over `pilot_id|seed|source_name|image_id|file_name` win. Selected images retain all associated annotations and their original image metadata. No class-coverage repair is permitted. The manifest stores the source and subset SHA256, selected image rows, counts, and a canonical selection hash. Input JSON order can change the subset file SHA256, but it cannot change selected image IDs or the canonical selection hash.

All generated output arguments must point inside this pilot directory. `make_subset.py` refuses to overwrite existing subset JSON or manifests. Use the exact grounding subset basenames `gqa_pilot10_v1.json` and `flickr_pilot10_v1.json`. Those names deliberately do not trigger the official class's full-dataset assertions.

Example on the later server (replace paths with real, absolute paths):

```bash
PILOT=/path/to/YOLOE-RCAP/pilot/v8s_10pct_v1
python "$PILOT/scripts/make_subset.py" --source-name Objects365v1 --input-json /data/objects365/annotations/train.json --dry-run
python "$PILOT/scripts/make_subset.py" --source-name Objects365v1 --input-json /data/objects365/annotations/train.json --output-json "$PILOT/data/objects365_pilot10_v1.json" --manifest-out "$PILOT/manifests/objects365_pilot10_v1.json"
python "$PILOT/scripts/make_subset.py" --source-name GQA --input-json /data/gqa/annotations/train.json --output-json "$PILOT/data/gqa_pilot10_v1.json" --manifest-out "$PILOT/manifests/gqa_pilot10_v1.json"
python "$PILOT/scripts/make_subset.py" --source-name Flickr30k --input-json /data/flickr/annotations/train.json --output-json "$PILOT/data/flickr_pilot10_v1.json" --manifest-out "$PILOT/manifests/flickr_pilot10_v1.json"
```

Run `verify_subset.py --subset-json ... --manifest ... --source-json ...` for each source, adding `--image-root` for strict image verification. The verifier fails on duplicate image IDs, orphan annotations, hash/count mismatch, and missing images. Duplicate filenames are permitted for GQA/Flickr30k. For Objects365, class coverage is counted from non-crowd annotations with segmentation polygons. Missing category 361 is an approved WARN: retain the exact deterministic subset without repair.

## Materialize Objects365

After the Objects365 subset and source images are available, run `prepare_objects365.py --subset-json ... --manifest ... --lock-out "$PILOT/PILOT_DATASET_LOCK.json" --pilot-data-root "$PILOT/data" --source-image-root /data/objects365/images/train --materialize`. This checks source image existence, hardlink capability, class coverage, category mapping, and filename collisions before writing the label/image tree. The hardlink preflight creates and removes only its own tiny file inside the pilot tree. It creates segmentation labels under `data/objects365/labels/train`, hardlinks selected images into `data/objects365/images/train`, and writes a usable pilot YAML inside `data`. It uses the official `merge_multi_segment` implementation, normalizes coordinates, skips crowd annotations, and de-duplicates identical labels. It never copies images. A failed hardlink stops with an error explaining that copying would be required. There is no automatic cleanup or overwrite mode; inspect any partial pilot output before a retry. The Objects365 lock section records real subset and manifest hashes, image and annotation counts, class coverage, YAML hash, label count, and a deterministic label-tree hash.

## Grounding cache and lock

Before building the real GQA cache, run `verify_gqa_official_images.py --subset-json "$PILOT/data/gqa_pilot10_v1.json" --manifest "$PILOT/manifests/gqa_pilot10_v1.json" --source-json /data/annotations/final_mixed_train_no_coco_segm.json --image-root /data/gqa/images --report-out "$PILOT/manifests/gqa_upstream_official_audit.json"`. It compares every selected record with the hashed official processed source and decodes every unique selected JPEG. Missing files, decode failures, duplicate image IDs, source/subset differences, and any new or changed dimension mismatch fail. The ten documented records on seven official JPEGs are reported as `WARN_UPSTREAM_OFFICIAL`, with `metadata_repaired=false` and `records_dropped=0`. The warning does not change JSON dimensions, normalized geometry, cache labels, or training inputs. The raw unsegmented grounding annotation is not required for this released-pipeline check.

For each grounding source, use the pilot wrapper, for example:

```bash
python "$PILOT/scripts/pilot_grounding.py" --subset-json "$PILOT/data/gqa_pilot10_v1.json" --manifest "$PILOT/manifests/gqa_pilot10_v1.json" --image-root /data/gqa/images --lock-out "$PILOT/PILOT_DATASET_LOCK.json"
python "$PILOT/scripts/pilot_grounding.py" --subset-json "$PILOT/data/flickr_pilot10_v1.json" --manifest "$PILOT/manifests/flickr_pilot10_v1.json" --image-root /data/flickr/images --lock-out "$PILOT/PILOT_DATASET_LOCK.json"
```

The wrapper verifies that every selected image exists and that the existing selected count equals the manifest's count **before** invoking the unchanged official cache generator. It refuses to overwrite a cache, then checks the multiplicity of each physical image path against the selected image_id records, verifies every cached label and records measured image and instance counts, subset/manifest/cache hashes, and absolute paths in the lock. The lock is created only from real verified data. `PilotGroundingDataset` inherits the official cache loading, transforms, collation, bounding-box and segment handling, and augmentation behavior. It replaces the hard-coded full-dataset verification with lock-based checks. A wrong official GroundingDataset invocation fails on the pilot filenames.

After GQA cache generation, run `verify_gqa_official_cache.py --subset-json "$PILOT/data/gqa_pilot10_v1.json" --image-report "$PILOT/manifests/gqa_upstream_official_audit.json" --report-out "$PILOT/manifests/gqa_official_cache_audit.json"`. The released generator produces 366,039 cache instances from 366,049 selected annotations: it suppresses six duplicate class-and-normalized-box entries and four zero-area boxes after JSON-based clipping. This pilot audit verifies those exact reasons and affected annotation IDs while requiring all 62,114 image records in the cache. These ten annotation filters are separate from the ten GQA dimension-warning records. Neither audit changes source records, cache geometry, or the released filter behavior.

The completed Flickr30k audit is recorded in `manifests/flickr_official_cache_audit.json`: all 14,891 selected records and 12,202 physical JPEGs passed source, decode, and dimension checks. The unchanged official generator retained all 63,741 annotations as cache instances; the real cache reloaded and segmentation samples passed. No metadata or records were changed.

## Pilot text artifacts

The pinned source's `RandomLoadText` constructor opens `tools/global_grounding_neg_cat.json`, `tools/mobileclip:blt/global_grounding_neg_embeddings.pt`, and `tools/mobileclip:blt/train_label_embeddings.pt`. Its `__call__` uses the label embedding map for selected prompts and samples global-negative embedding rows when padding to 80. The pinned MobileCLIP constructor asks for `mobileclip_blt.pt` relative to the process working directory. The official generation scripts collect Objects365 YAML class aliases and all grounding cache texts, encode them with MobileCLIP, and use a full-data frequency threshold of 100. **Do not run those official scripts for this pilot.**

Run `prepare_text_embeddings.py --lock "$PILOT/PILOT_DATASET_LOCK.json" --objects-manifest ... --gqa-json "$PILOT/data/gqa_pilot10_v1.json" --flickr-json "$PILOT/data/flickr_pilot10_v1.json" --mobileclip-weights /path/to/mobileclip_blt.pt --output-root "$PILOT/data/text/mobileclip_blt"` on the later preparation server. The script verifies the three locked pilot sources, then reads only the pilot Objects365 YAML and pilot GQA/Flickr caches for text. It uses the official `build_text_model("mobileclip:blt")` encoder, tokenization, and normalized text features. Its global-negative frequency threshold is `max(1, round(100*0.10)) = 10`, an intentional 10%-pilot adaptation intended to preserve approximately the same frequency threshold under image subsampling. It requires at least 80 global-negative names for the pinned `RandomLoadText` padding behavior. It writes all three artifacts inside the pilot tree, records their hashes and the MobileCLIP checkpoint hash in `text_artifacts`, and records the known LVIS identity in `evaluation`. It never overwrites official `tools/` artifacts.

`PilotRandomLoadText` inherits the official sampling `__call__` unchanged. Its constructor loads only the three locked pilot artifact paths; `train_pilot.py` routes dataset transform construction to this class at runtime. The prepared caches, lock, YAML, and MobileCLIP checkpoint use absolute paths. **Prepare and train on the same rented server at the same absolute paths.** A move or changed hash fails preflight; no cache path is rewritten silently.

## GPU protocol later

The training entry point requires a physical batch chosen intentionally after GPU smoke tests. `smoke_batch.py` prints trials in order 32, 16, 8 by default; `--execute` actually runs the trials on the rented GPU. Pass all `train_pilot.py` dataset/lock arguments, including `--mobileclip-weights`, after `--`. A smoke trial is one epoch at `fraction=0.001` of the already fixed pilot datasets. It initializes the real model and datasets and executes the pinned training forward/backward/optimizer loop. The pinned trainer forces validation and checkpoint calls on its final epoch, even with `val=False` and `save=False`, and calls `final_eval` after training. The pilot smoke subclass bypasses only those calls and the validation dataloader; it does not perform LVIS validation, scientific evaluation, or normal checkpoint saving. The grounding subclass fully verifies each locked cache **before** reducing labels to a deterministic runtime prefix for smoke; main training at `fraction=1.0` uses the complete locked 10% caches. Smoke never changes a manifest or cache. A trial returns exit code 75 only for a CUDA out-of-memory RuntimeError; only then does `smoke_batch.py` retry 16 or 8. Any other failure stops immediately with its traceback. Inspect GPU memory and the run result before selecting a batch; no RTX 3090 batch is claimed safe here.

`train_pilot.py` requires the Objects365 subset JSON, manifest, flat hardlinked image root, rendered YAML, the two grounding subset JSONs/manifests/image roots, the MobileCLIP checkpoint, the **complete five-section lock** (`Objects365v1`, `GQA`, `Flickr30k`, `text_artifacts`, `evaluation`), and `--physical-batch`. Its preflight checks hashes, counts, strict image and cache paths, Objects365 class coverage and labels, all pilot text artifacts, MobileCLIP weights, and both known LVIS minival hashes. It uses official `YOLOE("yoloe-v8s-seg.yaml")`, official scale overrides, `YOLOESegTrainerFromScratch` through the pilot subclass, `task=segment`, `imgsz=640`, `epochs=30`, AdamW, `lr0=0.002`, `warmup_bias_lr=0`, `momentum=0.9`, `close_mosaic=2`, seed 0, deterministic true, device 0, and full `lvis.yaml` validation. Training outputs are confined to `runs/main_batch_<physical>`; smoke outputs use `runs/smoke_batch_<physical>`. An existing run directory is rejected.

The official run supplied `weight_decay=0.025`, `batch=128`, `nbs=64`, and `accumulate=1`, giving scaled optimizer weight decay `0.025*128/64=0.05`. The pilot uses `nbs=128`, explicit physical batch 32/16/8, accumulation 4/8/16, and **pilot weight-decay argument 0.05**, giving expected scaled optimizer weight decay `0.05*128/128=0.05`. Accumulation varies during warmup. This preserves approximately the update sample count and scaled weight decay; it is **not mathematically identical** to 8-GPU DDP. Record the selected batch in experiment reports. No official optimizer or trainer source is edited.

The later server must retain the official relative LVIS layout at `../datasets/lvis/minival.txt`; preflight requires exactly 4,809 entries and SHA256 values `1b7c59904861001d0c0d71a024cee80617a4a74f565b38e9ab6c60d63123c4df` for the list and `02301f6ccd89d1ee3d35112cb57d000c3396f34e4073066c90b2c1fbf47b55ce` for `lvis_v1_minival.json`. Do not use a smoke trial as the main experiment or run this entry point on the preparation laptop. Never delete source data to make room. If space is insufficient, stop and report the needed space and candidate files for human review.

## Full Fixed AP after training

On the later GPU server, run `python "$PILOT/scripts/eval_pilot.py" --checkpoint "$PILOT/runs/main_batch_<selected>/weights/best.pt" --lock "$PILOT/PILOT_DATASET_LOCK.json" --name full_fixed_ap`. The checkpoint must exist; the name must designate a new output directory under `runs/eval`. CPU preflight verifies the checkpoint SHA256, both locked LVIS hashes, 4,809 distinct image paths and matching annotation IDs, and the unchanged baseline bbox validator source before loading the model. The model must be YOLOE-v8-S segmentation with the official v8 architecture and MobileCLIP text model. The run uses the validated `BBoxFixedAPValidator` from `reproducibility/yoloe_v8_sml_20260905/scripts/bbox_inference.py` without editing it, with the exact full-minival `640 / batch 1 / rect=False / conf=0.001 / iou=0.7 / max_det=1000 / half=False / load_vp=False / save_json=True / plots=False` configuration. Baseline-only import/cache paths are isolated, and derived caches stay in the pilot run. The wrapper checks visit order/count and invokes the unchanged `tools/eval_fixed_ap.py --type bbox` on `predictions.json`. It writes `fixed_ap_result.json` with AP, APr, APc, APf in AP points, checkpoint and input hashes, model identity, and protocol metadata. This is the validated bbox-only serialization workaround for the segmentation JSON mask issue; it is not mask AP. No one-image result is reported as scientific.

`data/`, `runs/`, `temp/`, Python caches, and review ZIPs *inside this directory* are ignored by its `.gitignore`. `PILOT_DATASET_LOCK.json` remains trackable. Existing review ZIPs beside this directory remain visible to Git; you may manually remove old review ZIPs before a final commit if desired. This preparation pass does not delete them.
