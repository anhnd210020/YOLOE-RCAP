# Region-wise Robust Vocabulary Training — method specification

This is a descriptive working name for a training-only experiment, not a novelty claim. The loss is implemented in this worktree. The starting source is YOLOE-RCAP commit `9a7065c3e8c75b358e023d84473cbd78de24e56f`. Development occurs in the `research/robust-vocab-v1` worktree, separate from the completed baseline. The baseline log reports 30/30 epochs and exit code 0; its worktree is unchanged.

## Baseline path and tensors

The Stage-1 text-prompt pilot uses `PilotTrainOnlyTrainer` through `PilotYOLOESegTrainerFromScratch`, `YOLOESegTrainerFromScratch`, and `YOLOESegTrainer`. Its model is `YOLOESegModel`. With `load_vp=False`, `YOLOESegModel.init_criterion()` selects `v8SegmentationLoss`. The classification BCE is in `ultralytics/utils/loss.py`, `v8SegmentationLoss.__call__`, at the assignment to `loss[2]`.

`pred_scores` is the actual pre-BCE classification-logit tensor, shaped `[batch, anchors, C]` after permutation; the class axis is `dim=2`. Its dtype is the head-output dtype. Training uses CUDA autocast when AMP is enabled, so numerical code must not assume FP32 logits. `target_scores` has the same shape and is generated by the task-aligned assigner under `no_grad` from detached predictions. A matched class can have a soft positive score. Define positive entries as `target_scores > 0` and negative entries as `target_scores == 0`. Negatives include every class on background anchors and non-matching classes on foreground anchors. The current pilot has `C=80` prompt slots, including sampled global-negative embeddings used to fill unused slots. The method must derive `C` from the tensor and support variable vocabulary size.

The exact baseline classification path is:

```python
target_scores_sum = max(target_scores.sum(), 1)
loss[2] = self.bce(
    pred_scores, target_scores.to(pred_scores.dtype)
).sum() / target_scores_sum
```

Here `self.bce` is `BCEWithLogitsLoss(reduction="none")`. The normalizer is the sum of **soft target scores**, floored at 1 by Python `max`; it is not a foreground count, anchor count, class count, batch size, or positive-entry count. The current classification path has no per-entry weight or mask: every included entry has effective baseline weight 1. Padding to 80 is done with actual global-negative embeddings, not masked-out logits. The box/DFL quality weights are separate from classification BCE weights.

## Proposed classification objective

For anchor/region `i`, class `c`, and the actual logit `z_ic = pred_scores[..., c]`, let the zero-target negative BCE be `ell_minus_ic = softplus(z_ic)`. Over valid negative entries, define their effective baseline weights `w_ic`, `B_i = sum_c w_ic`, and `q0_ic = w_ic / B_i` when `B_i > 0`. In the currently audited path, `w_ic = 1` for every negative entry and `B_i` is the number of such entries on anchor `i`; neither a fixed `C` nor a universal `B_i` may be assumed.

For finite `tau > 0`, define

```text
R_tau(i) = log(sum_c q0_ic * exp(tau * ell_minus_ic)) / tau

L_cls_tau = [full_positive_BCE_sum + sum_i B_i * R_tau(i)]
            / max(target_scores.sum(), 1)
```

Only the aggregation of negative classification BCE entries changes. `full_positive_BCE_sum` uses the complete baseline BCE for soft positive targets, rather than a hard-label or simplified positive term. Anchors with `B_i = 0` contribute zero robust-negative loss and require no division by `B_i`. The factor `B_i` preserves the baseline negative-loss scale as `tau` tends to zero. Existing box, segmentation, DFL, gain, batch scaling, assignment, and optimizer behavior remain unchanged.

**Exact dispatch invariant:** `robust_vocab_tau == 0` must execute the original classification BCE expression above directly, with its original operation ordering and normalizer. It must not use a small positive `tau` or a numerical limit approximation. Nonzero `tau` selects the robust-negative branch only.

## Numerical and validation requirements

- Validate that `robust_vocab_tau` is a finite, nonnegative scalar; a generic float-key type check alone is insufficient.
- Evaluate the `tau > 0` logarithmic moment with a stable log-sum-exp formulation, avoiding direct exponentiation overflow. Handle the `B_i = 0` case without `log(0)`, division by zero, or a gradient-bearing invalid value.
- Account explicitly for AMP and low-precision logits. Use sufficient precision for the robust reduction while preserving the direct baseline path at `tau == 0`; check finite forward values and gradients at representative logits and `tau` values.
- Test `tau == 0` **scalar and gradient equivalence** against the unmodified baseline classification expression, including soft positives, background anchors, mixed foreground/background anchors, empty-positive batches, and variable `C`. The direct branch should match the baseline under the same dtype/autocast conditions.
- For `tau > 0`, test the per-anchor `B_i` factor, positive BCE preservation, zero-negative handling, normalizer preservation, and gradient finiteness. The existing CPU suite reported 11 passes before this resume; the source files were unchanged at the resume audit. This pass does not rerun that suite.

## Paired A1/A3 experiment semantics

`A1` uses original YOLOE BCE with `robust_vocab_tau=0.0`; `A3` uses the robust-negative aggregation with `robust_vocab_tau>0`. They are **parallel runs from the same initialization**, not an A3 continuation from an A1 checkpoint. Hold initialization, dataset lock, training samples, seed, epochs, optimizer, LR schedule, batch policy, augmentations, trainable parameters, AMP/EMA behavior, and evaluation protocol fixed. Only `robust_vocab_tau` and its negative-loss aggregation may differ. Use separate run outputs and record the chosen value in run arguments and checkpoints. A paired-run wrapper must account for the current pilot entry point's refusal to reuse an output directory; this specification authorizes no run, resume, or data operation.

The method adds **zero learnable parameters** and changes training classification loss only. Inference must retain the existing YOLOE forward path, heads, RepRTA forward/fusion, prompt handling, LRPC, SAVPE, NMS, and postprocessing. The current pilot bypasses in-training mask validation because of an environment-specific OpenCV mask-resize failure and uses a separate locked LVIS **bbox Fixed-AP** evaluation. That bbox protocol must be identical for A1 and A3; it does not by itself establish a segmentation-AP result.
